# 추가 전략 후보 분류 (구현 전 리서치)

## 목적
전략을 확장하기 전에, 후보 지표/전략들이 어떤 데이터 소스 레이어에 속하는지 먼저 분류한다.
아직 구현 계획은 아니고, 다음에 실제로 하나씩 설계할 때 참고할 리서치 기록이다.

## 레이어 정의
- **A. 업비트 API 직접 조회** — 추가 계산 거의 없이 그대로 가져다 씀.
- **B. 파생(atomic → variant)** — 업비트에서 이미 받는 캔들/틱 데이터 위에 새 계산식만 얹으면 됨.
  지금 `engine/indicators/*.py`가 SMA/ATR/MARKET_TREND를 만드는 것과 같은 자리.
- **C. 외부 API/MCP 필수** — 업비트에 원천 데이터 자체가 없음.
- **D. 조건부** — 코인/상황에 따라 A(또는 B) 또는 C로 갈림.

## 분류 결과

| 항목 | 레이어 | 근거 |
|---|---|---|
| 시가총액 | **C** | 업비트 API엔 유통량 데이터가 없음(`docs/superpowers/specs_v1/2026-07-25-segment-size-analysis-design.md`에도 "업비트 API는 시가총액을 제공하지 않는다"고 이미 명시돼 있고, 그래서 `trade_value_24h`를 규모 대리지표로 씀). CoinGecko/CoinMarketCap류 필요 |
| 비트코인과의 상관계수 | **B** | KRW-BTC 캔들 + 대상 코인 캔들로 롤링 상관계수만 계산. `engine/indicators/market.py`의 `MARKET_TREND`가 이미 "KRW-BTC 캔들을 extra 라인으로 병합"하는 파이프라인을 갖고 있어, 그 구조를 재사용하고 공식만 rolling correlation으로 바꾸면 되는 전형적인 atomic→variant 사례 |
| 테더(USDT/KRW)와의 상관계수 | **B** | 업비트에 `KRW-USDT`(테더) 마켓이 실제로 상장돼 있음(`GET /v1/market/all`로 확인 완료). MARKET_TREND와 완전히 같은 패턴으로 대상 코인 캔들 + `KRW-USDT` 캔들을 병합해 롤링 상관계수만 계산하면 됨 — 외부 데이터 불필요 |
| 김치프리미엄 | **C** | "국내가 vs 해외가(USD 환산)" 비교인데, 정확히 하려면 실제 원/달러 환율(외부 forex)이나 해외 거래소(예: 바이낸스) USD 시세가 필요. 업비트 `KRW-USDT` 시세가 "업비트 내부 암묵환율"의 근사치가 되긴 하지만, 그것만으론 "정상 환율 대비 프리미엄"을 말할 수 없어 외부 기준환율이 있어야 함 |
| 시장심리(뉴스검색+감성분석) | **C** | 뉴스/소셜 API + 감성분석(NLP) 필요. 웹서치 MCP + LLM 감성 스코어링 조합으로 구현 가능한 영역 |
| 피보나치 되돌림 | **B** | 최근 스윙 고점/저점(캔들 high/low)만 있으면 계산되는 순수 가격 파생 지표. SMA/BB와 같은 자리에 새 지표로 추가 가능 |
| CMA/공포탐욕지수 | **C** | Fear&Greed Index는 변동성·모멘텀·소셜·도미넌스·검색트렌드 등을 조합한 제3자 합성지수라 업비트 데이터만으론 재현 불가. "CMA"가 정확히 무엇을 가리키는지는 아직 불명확 — 나중에 확인 필요 |

### 선행지표류

| 항목 | 레이어 | 무엇을 포착하는가 (목적) | 왜 이 레이어인가 (근거) |
|---|---|---|---|
| 호가창 잔량 | **A** | 매수/매도 호가 잔량으로 즉시 수급 불균형을 봄 | `/v1/orderbook`으로 실시간 스냅샷 직접 조회 가능. 단 **과거 호가창을 조회하는 API가 없어** 캔들처럼 백테스트에 못 쓰고 라이브 신호 전용으로만 의미 있음 |
| 체결강도(Volume Power) | **B** | 단순 거래량이 아니라 **체결 건별로 매수 체결인지 매도 체결인지**의 비율을 실시간 추적 — 지금 이 순간 매수세/매도세 중 어느 쪽이 우세한지를 봄 | `/v1/trades/ticks`의 매수/매도(`ask_bid`) 체결 틱을 집계해 매수체결량/매도체결량 비율만 내면 됨. 백테스트에선 각 시점까지의 과거 틱을 그대로 재구성하면 "그 시점의 실시간 체결강도"를 그대로 복원할 수 있음 |
| VPIN (Volume-Synchronized Probability of Toxicity) | **B(난이도 상)** | 시간이 아니라 **거래량 기준으로 구간(volume bucket)을 나눠** 매수 주도 거래와 매도 주도 거래의 불균형을 측정 — 급락/급등이나 변동성 폭발 "직전"의 정보거래(toxic flow) 징후를 포착 | 데이터 소스는 체결강도와 같은 체결 틱(`ask_bid`, 체결량)이지만, 시간이 아니라 거래량 기준으로 버킷을 나누고 매수/매도를 분류하는 알고리즘이 추가로 필요해 체결강도보다 구현 난이도가 훨씬 높음 |
| Volume Profile (VPVR) | **B** | 시간이 아니라 **가격대별 거래량**을 집계. 거래량이 적었던 구간(Low Volume Node)은 가격이 빠르게 통과하고, 거래량이 몰린 구간(Point of Control, POC)은 반등/저항이 일어날 확률이 높다는 게 활용 근거 | 캔들·체결 거래량을 가격대별로 누적하는 계산 — 업비트 캔들·틱 데이터만으로 충분 |
| Pivot Points & Fibonacci Retracement | **B** | 전일/전주 고가·저가·종가로 **오늘의 지지/저항선을 수학적으로 미리 그어두는** 지표. 계산 자체는 과거 데이터 기반(후행)이지만, 오늘 가격이 그 선에 닿았을 때 반응을 미리 대응하는 용도로 쓰여 선행지표류로 묶임 | 전일/전주 고/저/종가만 있으면 계산되는 순수 캔들 파생 공식, 캔들 데이터만 있으면 됨 |
| 거래소 입출금량(고래/민간지갑) | **C** | — | 온체인 데이터 — Etherscan/Whale Alert/Glassnode/CryptoQuant류 연동 필수. 업비트는 거래소 API라 온체인 데이터가 없음 |
| 미결제약정&펀딩비 | **C** | — | 업비트는 현물(spot) 거래소라 애초에 선물 상품이 없음 → 이 데이터가 업비트에 원천적으로 존재하지 않음. 바이낸스 선물 등 외부 파생상품 거래소 API 필요 |
| 감정 분석 | **C** | — | "시장심리" 항목과 사실상 같은 카테고리(뉴스/소셜 API + NLP) |
| 구글 트렌드 검색량 | **C** | — | Google Trends 관련 API/MCP 필요 |

**"선행지표류"로 묶인 이유**: 위 B 레이어 지표들은 전부 계산 자체는 과거(캔들/체결틱) 데이터 기반이라는 점에서 "후행"이다.
다만 산출된 값을 앞으로 벌어질 가격 행동(반등/저항/변동성 폭발)을 **예측하고 미리 대응하는 데 쓴다**는 점에서 선행적으로
활용된다 — 이건 "데이터를 어디서 가져오는지"(레이어 축)와는 다른 축이라, B 레이어 분류 자체엔 영향을 주지 않는다.

## 상관계수 계산 방법론 (BTC/테더 상관계수 공통)

**"daily 등락률"로 고정하지 않고, 선택한 봉 타임프레임의 등락률을 그대로 쓴다.**

1. **원가격이 아니라 수익률(등락률)로 계산한다.** 원가격은 추세(비정상성) 때문에 서로 무관한 두 코인도
   둘 다 장기 우상향하면 상관계수가 허위로 높게 나온다. 그래서 상관계수는 항상 등락률 기준으로 낸다.
2. **등락률의 봉 간격은 이 지표가 붙는 캔들의 timeframe을 그대로 따른다.** 이 앱은 `get_candles(market, timeframe, ...)`로
   15분봉/시간봉/일봉 등 사용자가 고른 timeframe 하나로 전부 캔들을 가져오는 구조라, 등락률도 "그 봉 대비 직전 봉"
   pct_change를 쓰는 게 일관적이다.
   - 15분봉 백테스트 → 15분봉 등락률끼리 상관계수
   - 일봉 백테스트 → 일별 등락률끼리 상관계수(흔히 말하는 "daily correlation"은 이 경우에만 해당)
   - 항상 "일별"로 고정하면 15분봉 전략에서도 일봉 데이터를 별도로 더 받아야 해서 지금의 단일 timeframe 캔들 구조와
     어긋나고 계산 비용도 늘어난다.
3. **등락률 정의는 기존 `MOMENTUM_PCT`(ROC100)와 동일하게 재사용한다.**
   ```
   등락률_t = (종가_t − 종가_{t-1}) / 종가_{t-1} × 100
   상관계수 = Pearson(대상코인 등락률_[t-N..t], 기준마켓(BTC or KRW-USDT) 등락률_[t-N..t])
   ```
   `period=N`(롤링 윈도우 봉 개수)을 다른 지표들처럼 파라미터로 노출하면 SMA/RSI의 `period`와 같은 자리가 된다.
4. **로그수익률(log return) 방식도 있으나 채택하지 않는다.** 통계적으로는 log return이 시간 가법성 때문에 더
   표준적이지만, 이 프로젝트는 이미 `MOMENTUM_PCT`에서 단순 %등락률(ROC100)을 쓰고 있어 일관성을 위해
   **단순 %등락률 기준 Pearson 상관계수**로 통일한다.

## 실무 참고 사항
- 이 프로젝트는 백테스트 엔진이 핵심이라, **레이어 A 중 "호가창 잔량"은 과거 데이터가 없어 백테스트가 불가능하고 라이브 매매에만 쓸 수 있다**는 점이 중요한 제약이다.
- 반면 캔들·체결틱 기반인 B 레이어(BTC/테더 상관계수, 체결강도, VPIN, Volume Profile, Pivot/Fibonacci)는 지금의 `get_candles()`/`upbit_data_service.py` 캐싱 구조를 그대로 확장하면 백테스트에도 쓸 수 있어, 구현 우선순위를 잡는다면 B가 가장 비용 대비 효과가 좋다.
- B 레이어 중 "MARKET_TREND처럼 다른 마켓 캔들을 병합해야 하는 지표"(BTC 상관계수, 테더 상관계수)는 `backend/main.py`의 `requires_market_data()` 패턴을 일반화(대상 마켓을 MARKET_TREND처럼 KRW-BTC로 고정하지 않고 지표별로 다른 보조 마켓을 요구하도록)해야 한다는 점을 설계 시 고려해야 한다.

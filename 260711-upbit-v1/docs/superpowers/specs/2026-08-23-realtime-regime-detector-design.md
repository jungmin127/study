# 실시간 장세 판별기 설계

## 목적

"장세별 프리셋 자동전환"(거래 전략 고도화)의 첫 단계. 라이브 데몬이 매 봉마다 "지금이 어떤
장세인지"를 인과적으로(그 시점까지의 데이터만으로) 판단할 수 있는 순수 함수를 만든다.

이 스펙은 **판별 로직 자체와 그 정확도 검증까지만** 다룬다. 판별 결과로 어떤 프리셋을
고를지(그리드서치 연계)와 실행 중인 라이브 전략이 실제로 조건셋을 갈아끼우는 메커니즘은
각각 별도 세션에서 브레인스토밍한다.

## 배경 / 문제의식

기존 `engine/trend_segments.py`(2026-08-16, `2026-08-16-trend-segment-analysis-design.md`)는
코인 전체 일봉을 ZigZag 스윙으로 상승/하락/횡보 구간을 잡고, 각 구간을 전반부/후반부로 나눠
9패턴으로 라벨링한다. 이 방식은 **완전히 후행적**이다 — "전반부/후반부" 판정 자체가 구간이
끝나야 나오는 사후 개념이라, 실시간 판별에는 원리적으로 이식할 수 없다. 코인마다 구간 길이가
들쭉날쭉한 것도 실시간 신뢰도 판단을 더 어렵게 만든다.

또한 `engine/segment_analysis.py:_compute_volatility()`(trend_segments가 재사용하는 함수)는
`datetime.now(timezone.utc)` 기준 최근 30일 변동성으로 `threshold_pct`를 계산해 2017년부터
현재까지 전체 역사적 구간에 동일하게 적용한다 — 이 라벨을 그대로 지도학습 데이터로 쓰면
미래 정보가 과거 라벨에 새어 들어가는 누수가 확정적으로 발생한다(코드로 확인됨).

## 지도학습 대신 규칙기반을 선택한 이유

`trend_segments`가 만드는 라벨은 코인당 상장 이후 전체 기간에서 수십 개 수준이고, 코인 간
동시 상관성이 커서 실질 독립표본은 더 적다. 코인시장은 사이클마다 성격이 달라(비정상성)
과거 사이클로 학습한 모델이 다음 사이클에도 통한다는 보장이 없다. 위 라벨 누수 문제까지
겹쳐, 지금 데이터 조건에서는 지도학습이 규칙기반보다 더 높은 예측 성공률을 보장하지 못한다
— 오히려 소량·상관·비정상 데이터에 복잡한 모델을 얹으면 과최적화로 실전 성능이 더 나빠질
위험이 크다(편향-분산 트레이드오프).

**결정:** 1차는 규칙기반 EWMA 스코어링으로 배포한다. 규칙기반은 결정론적 순수 함수라
학습이나 데이터 축적 기간 없이 과거 캔들 전체로 지금 바로 정확도를 검증할 수 있다 —
지도학습처럼 "데이터가 쌓일 때까지 기다렸다가 재검토"할 필요가 없다. 이 검증 결과가
부족하면 그때 지도학습(또는 하이브리드)을 별도로 재논의한다.

## 판별 로직 (`engine/regime_detector.py` 신설)

순수 함수 모듈 — 캔들 DataFrame을 인자로 받고 I/O가 없다. 백테스트/그리드서치/라이브 데몬
어디서든 동일 함수를 재사용할 수 있게 한다(⑤-2 signal_engine이 "백테스트와 라이브가 같은
함수를 쓴다"는 원칙을 지킨 것과 동일한 설계 철학 — 이후 세션에서 라이브 전환에 이 함수를
그대로 꽂을 수 있어야 한다).

```python
def compute_regime_probs(df: pd.DataFrame, half_life_bars: float) -> dict[str, float] | None:
    """df: candle_time 오름차순, close 컬럼 포함(get_candles()가 반환하는 형태 그대로).
    워밍업(half_life_bars * WARMUP_MULTIPLIER) 미만이면 None(판단불가) 반환."""
```

- **위험조정 모멘텀 스코어**: `momentum_ewma = returns.ewm(halflife=half_life_bars).mean()`,
  `volatility_ewma = returns.ewm(halflife=half_life_bars).std()`,
  `score = momentum_ewma.iloc[-1] / max(volatility_ewma.iloc[-1], _MIN_VOLATILITY_FLOOR)`
  (0-나눔 가드). 변동성으로 나눠 정규화하므로 변동성이 다른 코인끼리도 같은 척도로 비교
  가능하다(`trend_segments.py`가 30일 변동성으로 threshold_pct를 정규화하던 것과 같은 원리,
  단 이쪽은 별도 함수 호출 없이 같은 시계열/타임프레임 안에서 자체 정규화한다).
  **정정(Task 3 최종리뷰, 2026-08-23)**: 최초 설계는 `volatility_ewma`를
  `returns.abs().ewm(...).mean()`(수익률 절댓값의 평균)로 정의했는데, 이러면 분자·분모가
  같은 가중치 구조라 삼각부등식에 의해 `score`가 항상 [-1, 1]로 갇혀 카테고리 대표값
  ±2.0(급상승/급하락)에 영원히 도달할 수 없는 버그가 있었다(구현 후 리뷰에서 실측 발견 —
  하루 +2%씩 오르는 추세와 +50%씩 오르는 추세가 똑같이 score=1.0을 냄). pandas 내장
  지수가중 **표준편차**(`.ewm().std()`)로 교체해 해결 — 표준편차는 이 방식으로 갇히지 않아,
  분산이 작고 방향이 일관된 강한 추세일수록 비율이 커져 실제로 급상승/급하락에 도달한다.
- **half_life_bars 환산**: `half_life_days = 1.0`(확정값, 상수)을 캘린더 시간으로 정의하고,
  호출 시점에 전략의 `timeframe`으로
  `half_life_bars = half_life_days * 86400 / timeframe_duration(timeframe).total_seconds()`
  로 환산한다(`upbit_data_service.timeframe_duration()` 재사용). 1시간봉이면 약 24봉,
  15분봉이면 약 96봉 — 타임프레임이 달라도 "체감 반응속도"는 동일하게 유지된다. 같은 코인도
  전략마다 타임프레임이 다르면 서로 다른 half_life_bars로 서로 다른 regime이 나올 수 있다
  (의도된 동작).
- **워밍업 부족 시 `None`**: signal_engine이 지표 계산 불가 시 "판단불가"로 조용히 넘기는
  기존 정책과 동일하게 맞춘다 — 워밍업 부족을 억지로 낮은 신뢰도 확률로 포장하지 않고
  명시적으로 "모른다"고 반환한다.
- **`_softmax_categorize(score)`**: 5개 카테고리(급상승/완만상승/횡보/완만하락/급하락) 대표값
  (`[2, 0.7, 0, -0.7, -2]`, 튜닝 가능 상수)과의 거리에 softmax를 적용해 확률 벡터를 산출한다
  (합계 1.0). `temperature` 파라미터로 분포의 뾰족한 정도를 조절(초기값 1.0, 튜닝 가능).

### 휩쏘(잦은 전환) 방지는 이번 스펙 범위 밖

half-life를 짧게(1일) 선택했으므로 봉마다 확률이 꽤 출렁일 수 있다. 이 판별기는 있는 그대로
정직한 확률을 매 봉 내놓기만 하고, "몇 봉 연속 유지돼야 실제로 프리셋을 바꿀지" 같은
디바운스/이력 로직은 다음다음 세션(라이브 전환 메커니즘)의 책임으로 분리한다(관심사 분리).

## 검증 (`scripts/regime_backtest.py` 신설)

목적: 판별기가 실제로 쓸모 있는지 지금 바로 과거 데이터로 확인. 학습이 아니라 "이미 정한
상수가 그럴듯한가"를 사람이 눈으로 보는 도구다(그리드서치 결과 뷰어들과 같은 성격, pytest
대상 아님).

1. 표본 코인 2~3개(변동성 성격이 다른 코인, 예: KRW-BTC/KRW-ETH/KRW-XRP) × 대표 타임프레임
   1~2개.
2. 각 코인 전체 캔들 이력을 불러와 매 봉 `t`마다 `compute_regime_probs(df.iloc[:t+1],
   half_life_bars)` 호출 — 그 시점까지의 데이터만 사용(인과성 보장, look-ahead 없음).
3. `None`이 아닌 시점만: 예측 카테고리(확률 최댓값)와 이후 `N_BARS`봉 실현수익률을 비교.
   `N_BARS = round(half_life_bars * N_MULTIPLIER)`(N_MULTIPLIER 초기값 튜닝 가능, half-life의
   2~3배 수준에서 시작).
4. **"맞다"의 기준**: 판별기가 산출한 5개 카테고리 대표값(`[2, 0.7, 0, -0.7, -2]`)과 동일한
   척도로 실현수익률을 정규화한 뒤, 그 값이 예측 카테고리의 구간 경계(카테고리 대표값 사이
   중간점) 안에 들어오면 적중으로 집계한다. 판별 스코어를 만들 때 쓴 것과 동일한 정규화·경계
   기준을 그대로 재사용해, "방향만 맞으면 적중"처럼 헐거운 기준으로 hit-rate가 부풀려지는
   것을 막는다.
   **정정(Task 5 최종리뷰, 2026-08-23)**: 판별 스코어(`compute_regime_probs`)는 **봉당**
   위험조정 모멘텀이다(EWMA 평균수익률/EWMA 표준편차, 둘 다 봉 단위). 반면 "실현수익률"은
   `N_BARS`봉에 걸친 **누적**수익률이다. 이 둘을 그대로 `실현수익률 / volatility_ewma`로
   정규화하면 분자·분모의 시간 스케일이 안 맞아(누적 vs 봉당, 대략 `sqrt(N_BARS)`배 차이)
   "판별 스코어를 만들 때 쓴 것과 동일한 정규화"라는 위 문장의 의도를 실제로 어긴다 —
   최초 문구(`실현수익률 / 이후 N_BARS 구간의 volatility_ewma`)가 이 모순을 담고 있었다.
   올바른 정규화는 **봉당 평균**으로 맞추는 것이다:
   `정규화값 = (이후 N_BARS 구간의 봉당 평균수익률) / (이후 N_BARS 구간의 volatility_ewma)`
   (즉 `실현수익률 / N_BARS / volatility_ewma`와 동일). 리뷰가 순수 랜덤워크(예측력 전혀
   없음) 시뮬레이션으로 옛 공식이 실제 3개 코인 콘솔 출력의 모든 수치(횡보 예측 비중
   99.6%, 횡보 hit-rate 3.7~4.1% 등)를 오차범위 내로 그대로 재현함을 증명해, 그 결과가
   "판별기가 무작위보다 못하다"는 실제 신호가 아니라 측정 자체의 결함이었음을 확인했다.
5. 출력: 카테고리별 hit-rate, 샘플 수, 확률벡터-실현수익률 상관계수(스케일에 무관해
   버그가 있어도 즉시 드러나는 지표라 반드시 포함), **예측 카테고리 × 실제 카테고리 분포**
   (실제 라벨이 어느 카테고리에 쏠려있는지도 함께 봐야 hit-rate 숫자를 오독하지 않는다 —
   Task 5 리뷰에서 이 출력이 없어 진단에 시간이 걸렸다). 콘솔 출력.

## 비범위

- **프리셋 매핑**(장세 타입별로 어떤 지표조합을 쓸지, 그리드서치 연계) — 다음 세션.
- **라이브 전환 메커니즘**(실행 중 전략의 조건셋 교체, 휩쏘 방지 디바운스, 자금/포지션
  연속성) — 다음다음 세션.
- **파라미터 자동튜닝**(half-life, N_MULTIPLIER, 카테고리 경계값/temperature를
  `regime_backtest.py`의 hit-rate를 목적함수로 자동 탐색) — 검증스크립트가 프로덕션화되고
  수동 상수가 그럴듯하다고 확인된 뒤, 별도 브레인스토밍으로 진행한다. 이미 있는
  `scripts/grid_search.py` 조합 탐색 인프라를 재사용하는 형태가 될 가능성이 높다. 검증도 안
  된 목적함수를 자동 최적화하면 숫자는 좋아 보이지만 실제로는 의미 없는 파라미터에 수렴할
  위험이 있어(과최적화), 사람이 먼저 결과를 눈으로 확인하는 단계를 반드시 거친다.
  **재보정 시 주의(최종 브랜치 리뷰 실측)**: `CATEGORY_REFERENCE_SCORES`와
  `TEMPERATURE`는 독립 변수가 아니라 같이 조정해야 한다 — `_softmax_categorize`가 L1
  거리 커널이라 대표값 간격을 좁히면서 temperature를 그대로 두면 모든 카테고리 확률이
  ~0.2로 뭉개져 신뢰도 수치가 무의미해진다.
- UI/API — 이번 세션 산출물은 엔진 모듈 + 검증스크립트까지만. 이후 세션에서 필요해지면 추가.
- 지도학습/하이브리드 — 규칙기반 검증 결과가 부족하다고 판단되면 그때 재논의.

## 테스트 (`tests/test_regime_detector.py`)

- **합성 시계열 방향성**: 단조 상승/단조 하락/횡보(순추세 없는 노이즈) 인공 데이터에서 각각
  급상승·급하락·횡보 카테고리가 최댓값 확률을 갖는지.
- **half-life 반응속도**: 같은 시계열에 half_life_bars를 다르게 줘서, 짧을수록 최근 급변에
  더 빨리 반응하는지.
- **코인 스케일 무관성**: 변동성이 크게 다른 두 합성 시계열이 "동일한 상대적 강도"의
  추세일 때 비슷한 확률 벡터가 나오는지(변동성 정규화 검증).
- **워밍업 부족 시 `None`**: 봉 수가 부족할 때 정확히 `None`을 반환하는지.
- **확률 벡터 합=1 불변식**: 어떤 입력에도 5개 확률의 합이 항상 1인지.

## 검증(수동)

- `scripts/regime_backtest.py`를 표본 코인들로 실행해 hit-rate가 최소한 무작위 추측(20%,
  5개 카테고리 균등)보다 유의미하게 높은지 확인한다.
- 합성 시계열(뚜렷한 상승/하락/횡보)을 손으로 만들어 `compute_regime_probs`를 직접 호출해
  결과가 상식과 맞는지 확인한다.
